# CSV 날짜 포맷터 재사용 검증

측정일: 2026-10-01. 수정 전 기준 서비스: `946a4db`.

## 변경과 출력 동일성

`exportReservationsCsv` 내부에서 `Intl.DateTimeFormat`을 한 번 생성해 해당 호출의 모든 날짜에 재사용한다. `sv-SE`, `Asia/Seoul`, 연·월·일·시·분·초 옵션과 `hourCycle: h23`, 기존 Date/string 변환을 유지한다. 요청 간 공유와 출력 문자열 캐시는 없다.

DB 조회·필터·CSV 정렬·10,000건 제한·헤더·열 순서·BOM·CRLF·이스케이프·수식 방어는 변경하지 않았다.

- 동일한 합성 예약 2,000건의 CSV **403,363바이트** 전체 문자열이 수정 전후 완전히 같았다. 빈 결과도 전체 문자열이 같았다.
- 데이터에는 KST 날짜 변경 직전과 자정, 연말·연초, 초 단위, Date 객체와 문자열, null 연락처, 쉼표·따옴표·줄바꿈·수식 시작 문자·기존 작은따옴표를 포함했다.
- 기존 CSV fixture와 가짜 DB를 공통 테스트 helper로 옮겨 테스트와 측정에서 그대로 재사용했다.
- 날짜 경계와 빈 결과의 전체 문자열, 잘못된 날짜의 RangeError 테스트는 수정 전에도 통과하는지 확인했다.
- 수정 후 호출당 포맷터 1개 생성 및 다음 호출에서 새 포맷터 생성도 검증했다.

## 측정 환경과 방법

- 동일 Windows x64 머신, AMD Ryzen 5 5600, RAM 32 GiB.
- Node.js 24.15.0, ICU 78.2, 기존 `tsx` 실행기. 별도 의존성 없음.
- DB는 동일한 `CsvDatabase` 가짜 데이터 어댑터로 대체하고 **실제 `ProductService.exportReservationsCsv` 전체 호출**을 측정했다.
- 고정 합성 데이터 준비·정렬은 측정 밖에서 수행했다. 서비스 호출 직전부터 CSV 문자열 반환까지 `performance.now()`로 측정했다.
- 전후 각각 워밍업 2회, 측정 7회. 측정 중 다른 검사·빌드를 동시에 실행하지 않았고 인위적 지연도 추가하지 않았다.
- 포맷터 생성 횟수는 시간 측정 후 별도 호출에서 계측했다. 파일 쓰기·출력 동일성 비교도 생성 시간에 포함하지 않았다.

## 로컬 검증 및 재측정

- Worker 테스트 111개, 마이그레이션 도구 테스트 24개 통과.
- `npm run check`, `npm run build` 통과.
- DB 변경이 없어 이번 작업에서는 PostgreSQL 통합 테스트를 추가 실행하지 않았다.

`worker`에서 기존 실행기로 `node node_modules/tsx/dist/cli.mjs scripts/benchmark-csv.ts before`를 수정 전 서비스에 실행하고, 동일 스크립트로 수정 후 서비스에 `after`를 실행한다. `after`는 저장된 기준 CSV와 빈 결과가 다르면 실패한다.

JSON 측정값과 합성 CSV는 Git에서 제외된 `worker/test-results/csv-before.*`, `csv-after.*`에 저장한다. 운영 데이터·DB 주소·자격증명은 사용하지 않는다.
