# 반복 예약 생성 DB 호출 최적화 검증

측정일: 2026-10-01. 기준 코드: `ce674a5`의 반복 생성 서비스.

## 변경 범위

- 반복 생성 트랜잭션 안에서 공간명을 한 번 조회하고 회차 생성 이력에 재사용한다.
- 기존 이력 helper의 원래 공간명 우선순위와 다른 호출자의 조회 방식은 유지한다.
- `FAIL_ALL`은 회차별 SAVEPOINT/RELEASE 없이 전체 트랜잭션으로 원자성을 보장한다.
- `SKIP_CONFLICTS`의 SAVEPOINT/ROLLBACK TO/RELEASE, 시간 충돌 취소 기록은 유지한다.

## 환경과 방법

- Windows x64, Ryzen 5 5600, 논리 CPU 12개, RAM 32 GiB, Node.js 24.15.0.
- Docker `postgres:17-alpine` 임시 컨테이너, 마이그레이션 V9 적용. 전후에 같은 컨테이너와 DB를 사용했다.
- Node `pg` 8.22.0에서 Docker 포트로 연결한 로컬 TCP, TLS 없음. 테스트 프로세스 시간대 UTC, 예약 정책 시간대 Asia/Seoul.
- 기존 `PgDatabase` 테스트 어댑터에 동일한 SQL 관찰 콜백을 전후 모두 사용했다. SQL 문자열만 분류하며 주소·자격증명·파라미터는 결과에 기록하지 않았다.
- SQL 호출 수는 애플리케이션이 DB에 보낸 호출 수다. 사전 조회, BEGIN/COMMIT을 포함하고 DB 트리거 내부 실행은 별도로 세지 않는다.
- 시간은 `createRecurrence` 호출 직전부터 COMMIT 후 서비스 반환까지다. 데이터 준비·정리와 사후 검증은 제외했다.
- 시나리오마다 워밍업 2회 후 5회 측정했다. 매 실행 전 해당 fixture 공간의 `testing-` 예약·반복 예약·이력만 정리하고 같은 충돌 데이터를 준비했다.
- 정상 설정 변경 서비스를 통해 2030-01-02~2031-01-02, 매일 09:00~18:00 운영을 설정했다. 예약은 매일 10:00~11:00이며 366회차는 기존 최대 366일 검증을 그대로 통과한다.
- 충돌 시나리오는 0, 10, …, 350번째 회차에 승인 예약 36건을 미리 준비했다. 이는 사전 검사에서 발견되는 충돌이다.
- 최종 측정 동안 빌드·다른 테스트를 동시에 실행하지 않았으며, 인위적인 지연은 넣지 않았다. 테스트 종료 후 설정을 복원하고 임시 컨테이너를 제거했다.

## 정확성 검증

- PostgreSQL 통합 테스트 75개 통과. 성능 테스트는 기본 실행에서 제외되며 별도로 전후 실행했다.
- 새 테스트 7개: 두 정책 정상 생성의 필드·이력·호출 수, FAIL_ALL의 실제 INSERT 충돌 후 전체 롤백, 두 정책의 중간 DB 오류 후 전체 롤백, SKIP_CONFLICTS의 INSERT 충돌 회복, 생성 중 다른 연결의 공간명 변경과 다음 요청의 새 이름 반영.
- INSERT 충돌은 사전 검사 후 실제 PostgreSQL에 충돌 예약을 넣어 검증했다. 중간 오류는 두 번째 이력 저장 시 실제 PostgreSQL의 division-by-zero 오류를 발생시켰다. SQL 결과를 모킹하지 않았다.
- SKIP_CONFLICTS INSERT 충돌 테스트에서 SAVEPOINT 3회, RELEASE 3회, ROLLBACK TO 1회와 생성 2건·취소 1건·이력 3건을 확인했다.
- 기존 통합 테스트로 정책 위반 회차 건너뛰기, 취소 이력 내용, 삭제 공간의 원래 이름 보존 및 일반 예약 수정·삭제 경로도 검증했다.
- Worker 단위 테스트 105개, 마이그레이션 도구 테스트 24개, `npm run check`, `npm run build` 통과.

## 재측정

마이그레이션을 적용한 **일회용 로컬** PostgreSQL을 준비한다. DB 이름은 `testing_`로 시작해야 한다. 주소와 자격증명은 외부에 출력하지 않고 환경 변수 `DATABASE_URL`로 제공한다.

`worker`에서 `TZ=UTC`, `RECURRENCE_BENCHMARK=1`을 설정한 뒤 다음을 실행한다.

```text
npm run test:postgres -- tests/postgres/recurrence-creation.benchmark.test.ts
```

결과는 Git에서 제외된 `worker/test-results/recurrence-benchmark.json`에 저장된다. 전후 코드는 동일한 테스트·계측과 DB 조건으로 각각 실행해야 한다.

## 한계

실제 로컬 PostgreSQL 측정이며 운영 네트워크, Neon 서버리스 연결, Cloudflare Worker 런타임, 동시 부하를 재현하지 않았다. HTTP 요청·응답 직렬화도 측정 범위 밖이다. 5회 표본의 로컬 서비스 실행 시간 감소를 운영 환경의 동일한 속도 향상으로 해석하면 안 된다.
